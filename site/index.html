§00

Test the payment flows a sandbox won't reach.

paybox is a local payment infrastructure emulator. Point an existing Paystack, Stripe, Flutterwave, Kora, Quid Payments, WeWire or Wise integration at localhost and drive pending mobile-money authorization, webhook retries, duplicate deliveries, timeouts, refunds and idempotency — deterministically, offline.

$npx paybox-emulator start

§01
FIG. 1

A charge, from initialize to signed webhook.

Every request drives a real state machine. A charge appends to an append-only event log, moves through the same canonical statuses the organic flow would, and emits the same signed webhooks — the payment row is a projection of that log, which is why the timeline, replay and audit trail are one mechanism rather than three. Step 03 is the one no sandbox gives you: time is a value you set.

§03
FIG. 2

The failure modes, on demand.

A non-2xx response or a transport error schedules a retry: exponential from one second, doubling, with full jitter across the lower half of each interval, up to five attempts. All of it is scheduled work in a durable job table — so one advance runs the whole ladder, and the jitter is drawn from the seeded random, which keeps the run reproducible.

A

Force every delivery to fail

paybox webhook fail http_500 — then advance the clock and watch the ladder above run to exhaustion.

B

Duplicate and reorder

paybox webhook chaos --duplicate true --out-of-order true — at-least-once delivery, reproduced honestly.

C

Race the response

paybox network latency 3000 — latency lands on the response, so the webhook reaches your app before the call that created it returns.

D

Replay a signed payload

paybox webhook replay whd_… — same bytes, same signature, new delivery.

E

Move a year in one call

paybox time advance 1y — a monthly subscription yields twelve invoices one calendar month apart, each payment stamped at its own period start.

§04

Seven providers, eight adapters — each partially implemented.

Partial means partial. Each contract page lists what is implemented, what differs from the real provider and what is absent; if something is missing from one, assume it is not there. Every adapter declares what it serves in a manifest, and a test fails if the manifest and the router disagree in either direction — so this schedule cannot overstate what the emulator answers.

Note · safety

No real money can move through this process. It has no code path that reaches a payment network, it refuses live API keys, it never stores a CVV, and it binds to 127.0.0.1 by default — warning if you bind it wider.

Generated credentials are labelled TEST/LOCAL, and the whole database is a file you can delete. The guarantees and their limits are stated in SECURITY.md.

§05
FIG. 3

One engine, eight adapters, one direction.

The engine knows nothing about providers: provider is a discriminator on a row. Anything an adapter needs from the engine arrives as an injected function — a status mapping, an instrument table, an authorization minter — never an import. No adapter can see another, and the engine sees none of them.

I

The event log is the source of truth

Append-only, with no UPDATE path. Every state change appends an event and updates the row inside one transaction.

II

Two statuses are always stored

One canonical status drives the state machine; the verbatim provider string is kept beside it, so an adapter echoes exactly what the real API would return.

III

The state machine is a table

Not code. Terminal states have empty transition lists, and failed → successful is reachable only through an explicit reversal.

IV

The balance is a fold

Over an append-only ledger, never a stored mutable number. A transfer reserves its amount when queued, so two queued payouts cannot spend the same money.

V

Amounts are integer minor units

Always. No FX conversion ever happens; a cross-currency quote is recorded, not computed.

VI

Nothing reads the wall clock

Date.now(), Math.random() and raw timers are banned by lint outside the time package. That is what makes time advance work and a seed reproduce a run byte for byte.
